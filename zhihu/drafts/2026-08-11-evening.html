1. 智谱 ZCode 用户破百万，全量重置用量限制

Z.ai 宣布其智能体编程环境 ZCode 用户数突破一百万，并为所有 GLM Coding Plan 订阅用户重置用量额度。

中国编程智能体的一个规模节点

北京时间周二上午，智谱 AI 的海外品牌 Z.ai 宣布，围绕 GLM 模型打造的智能体编程环境 ZCode 用户数已突破一百万。作为回馈，公司为所有 GLM Coding Plan 订阅者重置了用量限制——相当于在计费周期中途给全部付费用户重新发了一份额度。Z.ai 同时表示正在推送一次更新，目标是让模型的长程能力真正转化为「干完的活」，而不是停留在长时间的尝试上。

ZCode 是智谱对标 Claude Code、Cursor 与 GitHub Copilot 的产品：一套终端与编辑器一体的执行框架，驱动 GLM 系列模型完成多步工程任务，支持 BYOK 接入第三方模型，并给 GLM Coding Plan 订阅者额外的用量加成。GLM Coding Plan 本身是智谱最成功的海外产品，定价远低于欧美同类，直接面向想从美国大模型订阅方案迁出的开发者。

真正值得读的是「重置」

百万用户是个数字，但重置额度这件事信息量更大。今年 1 月，智谱曾因算力紧张限制 GLM Coding Plan 的新用户注册——对一家正积极争取海外开发者的公司来说，这种公开承认相当罕见。七个月后反过来加送额度，说明推理侧的瓶颈已经缓解，无论是靠服务效率优化、卡的增加，还是两者兼有。

这件事的意义超出一家公司。编程智能体已经成为中国大模型公司出海最主要的变现切口：直接收硬通货、不需要做消费级 App、对品牌的依赖也相对低。单一国产框架跑到百万用户量级，而且有余力「送」而不是「限」，意味着中国开放权重阵营在国际市场上的约束正从算力供给转向产品与信任。同时，这也让欧美编程智能体订阅的定价更难受——对手仍在精细计量用量，而一个 MIT 协议的替代方案会时不时把计量器归零。

2. 阿里推出 Wan CLI，把视频生成塞进智能体工作流

阿里通义万相发布命令行工具 Wan CLI，智能体可直接以编程方式调用其图像与视频模型，安装只需粘贴一条命令。

让视频生成变成一个可调用的工具

阿里通义万相团队周二发布了 Wan CLI——一个命令行工具，让 AI 智能体可以直接调用万相的图像与视频生成能力，而不必再走网页界面。团队给出的安装方式本身就是为智能体设计的：登录 wan.video，在界面左下角找到 CLI 入口，复制那条命令，粘贴给你的智能体，由它自己完成安装。

装好之后，智能体就能在更长的流程中以编程方式生成图像和视频：批量编排镜头、拿到结果后再迭代提示词，或者把生成环节直接接进构建流程。此前万相已经开源了 Wan-skills 仓库（Apache 2.0），覆盖 Wan 2.7 图像模型与文档转 PPT 等技能，加上百炼平台上的 DashScope API。CLI 把这些散落的接入面收拢成了一个可安装的入口。

配合这次发布，团队还放出了 Wan-Animate-2-Lite 的新演示。这是 8 月 7 日开源的角色动画模型的效率版本，官方称其可以分块生成任意长度的序列，且观察不到误差累积——对数字人直播、实时虚拟主播这类场景来说，这个特性比固定时长的成片更关键。

为什么重要

到目前为止，生成式视频基本是按「目的地产品」卖的：你打开一个网站、花掉一些积分、下载一段片子。而现在真正浮出水面的竞争问题是：当一个任务恰好需要动态画面时，智能体会默认去调谁的模型。这是一场经济结构完全不同的分发战——被装进智能体工作流的一方拿到的是反复发生的程序化调用，而不是一次次独立的创作会话，并且会沉进别人换起来很麻烦的管线里。

阿里在这件事上动手较早，位置也比较特殊：它同时提供任何人都能自部署的开放权重和托管 API，因此智能体接入既能喂给付费端点，也不堵住本地使用的路。Runway、快手可灵与字节 Seedance 则更多在通过平台合作与第三方画布扩张。一个 CLI 的体量远小于一次模型发布，但它瞄准的正是 AIGC 与智能体工具链正在合流的地方。

3. Muse Glimmer 竞技场首秀成绩落在中游

Arena 首次给出人类偏好评分：Meta 新开源模型 Muse Glimmer 在 Code Arena WebDev 位列第 77、文本竞技场第 97，开源模型中分别排第 26 和第 24。

Meta 重回开放权重后的第一份外部成绩单

Arena 在北京时间周二凌晨放出 Muse Glimmer 的首份人类偏好评分，距 Meta 以 Apache 2.0 协议发布这个 300 亿参数模型仅一天。在 Code Arena 的 WebDev 榜上，该模型以 1359 分首发第 77 名，在开源模型中排第 26；在文本竞技场以 1426 分位列总榜第 97，开源模型中排第 24。

Muse Glimmer 是 Meta 一年多来最重要的开源动作，也是其战略重新转向开放权重的具体落点。它的定位是本地常驻的智能体工作，而不是刷聊天榜：约 300 亿参数，其中含 18 亿参数的视觉编码器，支持多模态输入，上下文超过 13.1 万 token，体量压到约 18GB，可在消费级硬件上通过 LM Studio 跑起来。Baseten 等托管商在首日就已上线。

这个定位让榜单成绩需要两面看。人类偏好类榜单奖励对话质感，且被体量大得多的前沿与准前沿模型占据，因此一个 300 亿参数的本地模型排在 70 名之外，本身并不能说明它在被设计去做的事上表现不佳——工具调用、函数结构遵循、多步任务完成，这些恰恰是这类榜单只能间接反映的能力。开发者的早期实测反馈中，它在智能体式代码探索上的口碑好于开放式创意生成。

为什么重要

但这毕竟是针对一次被 Meta 定义为「战略重置」的发布给出的首个外部数据点，而角度并不好看。在开源模型中排到第 24 至 26 名，意味着 Glimmer 首发时明显落在中国开放权重阵营之后——Kimi、GLM、千问以及 DeepSeek 衍生模型，正是这一年来在定义「前沿开源模型该是什么样」的那一批。Meta 为这次转向给出的理由是要在这条赛道上比它们跑得更好，而不是在最终必然被拿来对比的榜单上落后。

Arena 本周还另外提到，闭源与开源模型的性能差距已收窄至历史最窄。而这轮收窄并不是发生在 Glimmer 身上——对 Meta 来说，这才是更扎人的那句。
