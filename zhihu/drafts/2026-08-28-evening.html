1. 腾讯开源混元 Hy4 Preview，上下文扩至百万 Token

腾讯发布混元 Hy4 Preview 开放权重，以 7700 亿总参数、490 亿激活参数和百万 Token 上下文主攻生产力智能体。

权重已开放，架构进一步扩容

腾讯正式发布混元 Hy4 Preview，并通过 Hugging Face、ModelScope、GitCode 和 CNB 提供完整精度及 FP8 版本权重。该模型采用混合专家架构，总参数量为 7700 亿，每个 Token 激活 490 亿参数，支持最长 100 万 Token 上下文。

Hy4 的每个混合专家层设有 256 个路由专家，每次激活其中八个及一个共享专家。注意力模块结合门控稀疏注意力与跨层索引复用，另有原生多 Token 预测层用于推测解码。腾讯同时给出了 vLLM 和 SGLang 部署方案，但如此规模的模型仍远超普通工作站的承载能力。

面向生产力智能体优化

腾讯将 Hy4 的重点场景放在编程、办公、游戏开发和科学研究。公司组织 163 名内部专家，对 203 项工程任务进行盲测；Hy4 平均得分为 2.99 分，略高于 GLM-5.3 的 2.92 分和 Kimi K3 的 2.94 分。不过，这组结果来自厂商内部测试，仍需独立评测验证。

腾讯还称，Hy4 参与了自身训练方法、数据策略、评估体系和底层算子的优化，并通过算子融合与通信优化，将端到端推理吞吐量较内部基线提高 31.8%。模型卡也明确列出当前缺陷，包括复杂任务中思考时间偏长，以及反复验证自身结论。

Hy4 已接入腾讯旗下产品、腾讯云 TokenHub 和 OpenRouter。官方 API 定价为每百万输入 Token 0.834 美元、输出 2.501 美元，缓存 Token 为 0.042 美元。

为什么重要

Hy4 为快速扩大的中国开放权重模型阵营增加了一个真正的大体量选手。百万上下文、面向智能体的训练和可下载权重，让研究机构与基础设施厂商能够实际检查和部署它。悬念在于运行效率：每次只激活 490 亿参数固然降低了计算量，但托管一个 7700 亿参数检查点依然需要昂贵的硬件资源。

2. Midjourney 向用户开放 V8.2 图像编辑模型测试

Midjourney 首款 V8.2 图像编辑模型开始扩大测试，支持文字指令修改、四图参考、局部重绘与画布扩展。

V8 系列迎来原生编辑模型

Midjourney 开始面向更广泛的社区测试首款基于 V8.2 的图像编辑模型。用户可以用文字指令修改现有图片、通过局部重绘替换指定区域、向原图边界之外扩展画面，还能同时使用最多四张图片作为视觉参考生成新图。

新的多图参考流程将在这类编辑任务中取代此前的 Omni Reference。个性化配置、情绪板和风格参考仍可使用，不过 Midjourney 提醒，测试阶段使用情绪板或风格参考时，可能需要写出更明确的提示词。

用户可以把图片拖入网页提示栏、在已有作品中点击编辑、通过独立编辑页面上传素材，也可以在 Discord 中使用编辑命令。Midjourney 还同步调整了主站与 Alpha 站点界面，说明此次测试覆盖的不只是模型本身，也包括围绕编辑任务重新设计的操作流程。

尚未定型，重点寻找边界问题

Midjourney 明确将此次开放定义为大范围社区测试，而非完成度稳定的正式版本。公司鼓励用户对失败结果给出负面反馈，并提交任务编号或链接，后续将快速迭代模型和界面。

这一点尤其重要，因为指令编辑的评价标准与自由生成不同：画面即使美观，只要误改了应保留的细节、混淆四张参考图的作用，或改变选区以外的内容，就不能算成功。Midjourney 目前尚未公布编辑忠实度、主体身份保持或多参考一致性等系统性指标。

为什么重要

这次更新让 Midjourney 进一步从提示词生成器转向可反复修改的视觉生产环境。原生编辑能够减少用户把生成结果转移到其他软件中返工的需求，多图参考也有望帮助创作者稳定复用角色与美术方向。它能否成为可靠的专业工具，取决于局部控制是否足够精准，而这正是此次社区测试需要暴露的问题。
