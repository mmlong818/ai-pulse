OpenAI 联手 Vercel 等推出 Agent Plugins 1.0 开放标准

该规范把 Agent Skills 与 MCP 服务器配置打包成一份可移植插件，首发支持 ChatGPT、Codex、Cursor、Copilot、Kiro 与 VS Code，谷歌同日加入技术指导委员会。

8 月 6 日，六家公司共同发布 Agent Plugins 1.0.0——一套开放规范，让智能体扩展只需打包一次，即可在互为竞争对手的各家客户端中通用。同一天，谷歌宣布加入该项目的技术指导委员会。

格式本身

一个插件就是一个目录：根部放 plugin.json 清单，必填字段只有两个（schema 版本与插件名）；技能放在 skills/ 目录，MCP 服务器配置写进 mcp.json，各客户端的私有扩展则通过命名空间字段承载。刻意的极简是设计要点——由目录结构而非庞大 schema 来承担契约，实现方接入成本被压到很低。1.0.0 版本只解决打包问题，并未定义安装机制、分发协议、权限模型或签名校验。

这份规范把此前分头传播的两样东西合到了一起：Agent Skills 是教智能体「怎么做某件事」的自然语言指令文档，MCP 服务器则负责暴露工具与数据。扩展作者过去不得不按各家客户端的约定反复重新打包，如今只需产出一份产物。

参与方

有三份名单需要分开来看。规范由 Vercel 发起，亚马逊云科技（AWS）、Anysphere（Cursor）、GitHub、微软、OpenAI 与 Vercel 的代表共同打磨至 1.0.0。首届技术指导委员会的范围更窄，由 AWS、Cursor、微软、OpenAI 与 Vercel 的核心维护者（Core Maintainer）组成；8 月 6 日，谷歌宣布以第六位核心维护者的身份加入该委员会，由 Google DeepMind 的 Kevin Hou 代表，并称其 Agents CLI 与 Data Agent Kit 已按该格式输出插件。首发支持该格式的客户端为 ChatGPT、Codex、Cursor、GitHub Copilot、Kiro 和 VS Code。治理流程与规范托管在公开仓库，文档见 agent-plugins.org。

三份名单里都缺同一个名字：Anthropic。该规范正是构建在其 Agent Skills 格式之上，而它的 Claude Code 是当下使用最广的编程智能体之一。Anthropic 既不在参与撰写的公司之列，也不在核心维护者名单中，Claude Code 亦非首发客户端——它使用自家的插件格式，可打包技能、hooks、MCP 配置、子智能体与斜杠命令，并配有官方插件目录。该公司尚未公开表态是否会采用 Agent Plugins。

为什么重要

MCP 统一了工具调用的传输协议，Agent Plugins 则试图统一它上面那一层——作者真正对外分发的那个「包」。如果标准立得住，插件生态就从各家的护城河变成可移植资产，智能体客户端将被迫在执行质量上竞争，而不是靠独占扩展留人。谷歌在一天之内加入，消解了最容易提出的那个质疑——这只是「OpenAI 及其盟友」的小圈子；但更尖锐的问题依然悬着：一个缺席了提供原始格式那家厂商的标准，能否真正做到中立。
