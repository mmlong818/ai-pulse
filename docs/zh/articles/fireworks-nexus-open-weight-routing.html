Fireworks Nexus 把编码 agent 的日常活分给开源权重模型

Fireworks AI 新推的控制层可将 Claude Code、Codex 的常规任务转投开源权重模型，称每个合并 PR 的成本能降三成。

Fireworks AI 于 7 月 28 日发布 Fireworks Nexus，这是一层夹在企业现有编码工具与其托管的开源权重模型池之间的路由与成本管控组件。

怎么运作

Nexus 的设计思路是「换个地址」，而非换一套客户端。团队把 Claude Code、Codex、OpenCode 或自研 harness 指向 Fireworks，原有工作流完全保留；路由器随后逐请求判断：这个任务是真的需要前沿模型，还是开源权重模型也能做到相当质量。外面再包一层 AI 支出控制面——按用户设上限、按席位统计用量、跨模型统一开通管理。

Fireworks 把问题定义为「错配」而非单纯超支：多数公司在用前沿模型的价格处理常规活儿，而换模型带来的运维负担，让平台团队即便在质量差距很小的情况下也不愿动开源权重这条路。

公司公布了与 Notion、Doximity 的早期落地数据，称每个合并 PR 的成本下降约三分之一。更值得注意的是一组对照结论：Claude Code 跑在智谱 GLM-5.2 上的表现略优于跑在 Opus 4.8 上，而每个完成任务的成本只有大约一半。这些数据均出自 Fireworks 自身，尚无第三方复现。

为什么重要

编码 agent 已成为企业 AI 预算中最容易被单独识别出来的大头，而它的成本随 token 消耗增长，而非随席位数增长。这让「路由」——而不是「选哪个模型」——成为财务负责人真正能按下的那个开关，也解释了为什么各家推理服务商都在抢占决策发生的这一层。

比产品本身更值得关注的是那组对照数据。如果一个中国开源权重模型能在西方编码 harness 里以一半价格打成平手，那么在常规工程任务上继续支付前沿模型价格的理由就会明显收窄，切换与否将更多取决于工具链是否顺手，而不是能力够不够。而这正是 Nexus 要抹平的摩擦——它指向的是这样一个市场格局：难题留给前沿实验室，用量则持续流向开源权重。
