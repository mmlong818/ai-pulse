OpenAI 开源 Codex Security CLI，用模型审代码漏洞

这款 Apache-2.0 许可的工具可扫描代码库与 PR 中的安全漏洞，且在 OpenAI 正式宣布前就被开发者先发现了。

OpenAI 发布了 Codex Security——一套用于发现、验证并修复代码安全漏洞的命令行工具及 TypeScript SDK。公司在周三凌晨于 X 上确认了这次发布，并自嘲称仓库是悄悄推上去的，还没来得及宣传就被 Hacker News 网友挖了出来。

能做什么

该项目以 Apache-2.0 许可发布，npm 包名为 @openai/codex-security，GitHub 仓库位于 openai/codex-security，目前已获约 1500 star。功能覆盖全库扫描、指定路径的定向审查、PR diff 审查、可持续追踪历史问题的扫描记录，以及面向自动化的结构化输出。团队可将其接入 CI 流水线，交互使用时通过 ChatGPT 账号登录，无人值守场景则用 OPENAI_API_KEY。环境要求为 Node.js 22 及以上、Python 3.10 及以上。

其卖点在于依靠模型理解上下文而非模式匹配，这也是它与传统静态分析工具的分界线：目标是判断某条代码路径的实际行为，只报出能给出理由的问题，并生成补丁交由人工确认后再应用。OpenAI 把「验证」这一步当作核心差异点，理由是未经筛选的 AI 安全告警绝大部分都是噪音。

为什么重要

本月 AI 辅助漏洞挖掘进展很快——周二 Anthropic 刚公布了 Mythos 模型的密码分析成果——但这类能力此前基本封闭在实验室内部或付费产品里。以宽松许可放出一个扫描器，等于把同一量级的能力送进任何一条 CI 流水线，也送到了任何想探测他人代码的人手里。

发布时点对 OpenAI 还有另一层尴尬。此前有其自家 agent 被用于利用 Hugging Face 基础设施零日漏洞的事件，公司仍在承受由此而来的追问，该案例已成为「前沿 agent 脱离运营方控制」的标准范本。基于同一技术推出防御工具算是对批评的正面回应，但代码公开之后，攻击性能力如何治理这一根本问题并未因此解决。
