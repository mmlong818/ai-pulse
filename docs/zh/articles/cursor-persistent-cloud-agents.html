Cursor 云端智能体新增长期目标与事件触发

Cursor 云端智能体现可响应 PR、Slack 和定时事件，持续追踪长期目标，并在隔离虚拟机中调度子智能体。

从等待指令转向事件驱动

Cursor 推出一组云端智能体及运行框架更新，让编程智能体不再需要用户逐步发起每项工作。云端智能体现在可以订阅拉取请求、Slack 对话和定时任务，在相关事件发生时自动唤醒。由智能体创建的拉取请求会被自动纳入跟踪范围；此后若持续集成测试失败，或审查机器人留下新意见，智能体可以继续处理，直至推进到下一状态。

新增的 /goal 命令允许用户设定一个持续存在的目标，要求智能体在完成前始终围绕该目标工作。Cursor 给出的示例包括修复全部不稳定测试，并让持续集成流程重新通过。长期目标还可与周期性检查及 Custom Modes 组合使用：后者会把某项技能固定在会话中，使智能体在长时间运行期间持续遵循同一套专业流程。

子智能体的隔离能力也得到扩展。被委派的智能体可以分别运行在独立虚拟机中，各自获得一份干净的项目副本和独立上下文。多个智能体因而能够并行测试或调查同一应用，而不会相互修改工作区。例如，主智能体可以安排多名子智能体分别寻找不同类型的缺陷，也可以让其中一个在全新环境里验证其他智能体提交的改动。

Cursor 还调整了运行中的引导方式。用户可以在智能体工作时补充指令，新消息会等到下一次工具调用边界再送达，而不是立即中断正在执行的动作，从而降低文件操作等任务被截断的风险。事件订阅功能目前仅适用于云端智能体。

为什么重要

这次更新推动编程智能体从交互式对话工具转向持续运行的软件工作者。真正关键的不是某一条命令，而是事件触发、长期目标、隔离委派和运行中引导被组合成了一套控制机制，使智能体能够在数小时甚至数天内维护拉取请求并响应开发事件。这有望减少重复协调工作，但随着智能体在无人即时监督时获得更多行动机会，权限范围、执行可观测性以及可靠的停止条件也会变得更加重要。
