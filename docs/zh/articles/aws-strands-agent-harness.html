AWS开源Strands Harness，打包智能体运行基础设施

AWS发布开源Strands Harness，预置工具、记忆和上下文管理，并声称在准确率相近时节省28% Token。

AWS开始打包智能体运行时

AWS发布Strands Harness，这是一个开源智能体Harness，旨在为开发者提供可直接使用的智能体构建和部署起点。该项目预置工具调用、上下文管理、会话、记忆、钩子和系统提示词等能力，开发者无需逐层拼装即可通过一次导入创建智能体。

项目支持Python和TypeScript，并允许开发者连接自行选择的模型。AWS将其放在更大的Strands工具链中，后者还包括底层Harness组件、评测工具，以及面向更安全操作系统交互的Shell。

成本主张仍需更多细节

AWS称，Strands Harness在任务准确率接近竞争方案的情况下，可减少28%的Token使用量。公司将其定位为面向工具调用、上下文维护和中间失败恢复场景的效率升级。不过，发布材料尚未披露完整评测细节，包括任务构成、模型配置，以及节省Token是否会换来额外延迟或基础设施成本。

该项目并不限定在单一AWS部署路径中运行。开发者可以搭配不同模型使用开源Harness，并自行调整工具、记忆和上下文策略。这一点很重要，因为智能体开发者越来越需要可迁移的应用逻辑，同时保留对部署方式、数据处理和模型选择的控制权。

为什么重要

智能体开发正从提示词设计转向运行时工程。工具权限、记忆行为、上下文压缩和失败恢复，往往决定一个智能体能否以可接受的成本稳定投入生产。AWS通过发布预组装Harness，争夺的是基础模型与业务应用之间的中间层。短期影响取决于开发者是否信任其默认设置，以及28%的节省能否在AWS评测之外的工作负载中重现。

猫叔判断

28%的Token节省很诱人，但评测细节尚不完整；当前更确定的产品价值是默认方案，而非普适效率结论。
