Claude Code 打通会话互通，多终端智能体可互发消息

新功能让一个 Claude Code 会话通过本地套接字把结论直接传给另一个会话，跨机器场景仅允许回复。

Anthropic 为 Claude Code 上线跨会话消息功能：正在运行的一个会话可以直接给另一个会话发送文字消息，用户不必再在多个终端之间手动搬运上下文。该功能需要 2.1.224 及以上版本，支持 macOS 与 Linux（含 WSL 2），满足条件后无需任何配置即自动生效。

模型手上多了两个工具：用 ListAgents 列出可触达的会话，用 SendMessage 按名称投递消息。用户可以主动要求发送——比如询问另一个终端里的数据库迁移是否完成——模型也可以在判断自己刚做的改动会影响其他会话的工作时自行发出提醒。传递的内容只有纯文本，不包含对话历史、文件或发送方的上下文。同一台机器上的会话通过各自的 Unix 域套接字通信，权限限定为当前操作系统用户，全程不经过 Anthropic 服务器；而要触达另一台机器或网页版 Claude Code 上的会话，则需经由 Anthropic 服务器，且只能回复，无法主动发起。

Anthropic 为这条通道设了多重围栏。收到的消息会被明确标注来自另一个会话而非用户，因此无法替用户批准待确认的权限请求，也不能要求接收方修改权限设置或 CLAUDE.md，消息里出现的斜杠命令只会被当作普通文本。消息要求的任何操作，仍需通过接收方自己的权限规则。crossSessionInbound 设置可选择接收、暂存或直接丢弃；默认情况下，绕过权限确认的会话会先把消息挂起等待人工批准。系统还对重复发送做了限流并去重，最多排队 50 条、挂起 100 条，避免两个智能体陷入互发死循环。管理员可通过托管设置关闭收发两端；该功能在 Amazon Bedrock、谷歌云 Agent Platform 和微软 Foundry 上不可用。

影响

开发者同时在多个 worktree 里跑好几个编程智能体已成常态，此前协同全靠人工。给会话之间开一条对等通道，等于把一组彼此隔离的智能体变成松耦合系统；同时它也新增了一条提示注入的传播路径——这正是设计上刻意把消息削减为纯文本、且不赋予任何批准或改配置权限的原因。
