OpenAI为人机并行开发打造Git后端Pando

OpenAI为自家单体代码库开发Pando后端，重点解决工程师与编码Agent并发推送、拉取和故障恢复问题。

为另一种工作负载重做Git后端

OpenAI在11月2日发布的工程文章中披露，公司已经开发出新的Git后端Pando，用于支撑其单体代码库中不断增加的人类工程师与软件Agent并发操作。

Pando保留了开发者熟悉的Git客户端工作方式，但改变了仓库数据的存储和传输方式。当客户端拉取更新时，系统会识别缺失的提交范围，并返回覆盖这段差距的packfile链接。当多名工程师或Agent分别向不同分支推送时，Pando可以并行处理；如果更新针对同一分支，则仍按顺序写入。

系统也针对失败恢复进行了设计。OpenAI表示，公司已将“packfile下载中断后的清理”相关修复贡献回Git项目。这说明Pando遇到的问题并非单纯的内部性能调优，而是自动化、高并发开发环境正在暴露传统工具的新边界。OpenAI称迁移后推送延迟明显下降，但文章没有给出完整的独立基准，也没有披露代码库的具体规模。

Pando的意义不在于Git本身，而在于它反映了OpenAI正在构建怎样的软件生产环境。编码Agent会制造突发性的自动提交、分支操作和仓库读取请求，而传统开发工具主要围绕人类协作设计。若能在不改变开发者接口的前提下并行处理这些流量，仓库后端将成为Agent密集型组织的重要基础设施。

为什么重要

这篇文章提供了一个具体信号：在Agent真正接管软件开发之前，它们已经先改变了日常工程操作的并发形态。未来代码托管系统可能首先为机器生成的高并发优化，而不只是为人类协作优化。

猫叔判断

比Pando这个名字更重要的是Git修复：下载中断之所以成了产品问题，是因为Agent让流水线几乎不停机。
