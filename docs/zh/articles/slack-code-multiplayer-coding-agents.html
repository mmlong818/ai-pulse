Slack Code让编程智能体进入团队协作频道

Slack推出共享编程频道，让整个团队都能查看智能体的执行过程、代码改动和运行预览，而不再局限于个人会话。

编程智能体走进共享工作区

Salesforce推出Slack Code，允许团队直接在Slack中向编程智能体分派任务并共同审查结果。成员在讨论中提及受支持的智能体后，Slack可创建专用的Code Channel，将需求对话、智能体所用上下文及其生成成果集中在一处。

频道内可展示代码修改前后的差异、代码仓库链接以及可运行的预览，并通过Slack画布供团队审阅。产品经理、设计师及其他相关人员因此能在方案成形期间就参与反馈，而不必等工程师结束一段封闭的终端会话后，再面对已经完成的实现。

Salesforce的发布页面将Anthropic的Claude、Cognition的Devin、GitHub Copilot、ChatGPT和Vercel的智能体列为Slack Code创始合作方。不过，这份发布名单并不等同于当前可用名单：Slack帮助文档目前列出的可创建Code Channel的获批智能体为Claude、Devin、GitHub Copilot和Vercel；Slack发布内容则说明OpenAI的ChatGPT接入仍将于稍后推出。这些Slack Code名单也不应与Slack应用市场中更广泛的AI应用名单混为一谈。Slack Code可在所有Slack套餐中使用，但客户仍须单独获得所选合作智能体的使用权限。Salesforce还计划向更广泛的开发者群体开放Code Channel接口，让更多自定义智能体参与其中。

Slack争夺智能体协作入口

过去已有智能体能够从Slack接收任务；此次更新更重要的变化，是为整个开发过程提供了跨厂商、可持续留存的协作记录。提示词、产品决策、修改意见与生成代码，都能保存在最初讨论问题的频道中。

这种透明度有望减少返工：智能体即使在技术上完成了提示词，也可能误解产品意图，团队如今可以更早纠偏。不过，企业也需要重新划定权限，明确各个智能体能够访问哪些代码仓库、对话和部署系统，以及最终由谁批准生成的改动。

这项发布的重要性还在于平台竞争。各家模型公司正在争夺开发者终端，而Salesforce希望让Slack成为凌驾于不同智能体之上的协调层。若这一模式得到采用，企业真正沉淀的资产将不只是智能体写出的代码，还包括解释这些代码为何产生的共享组织上下文。
