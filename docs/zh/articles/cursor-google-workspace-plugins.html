Cursor 上线 Workspace 插件，智能体可读写 Gmail 与云端硬盘

Cursor 发布 Google Workspace 插件，让其智能体可直接读写 Gmail、Drive、日历、Docs、Sheets 与 Chat，把编码工具推向通用知识工作。

上线了什么

Cursor 于 8 月 3 日发布一组 Google Workspace 插件，让其智能体获得用户 Google 账号的直接读写权限。据官方更新日志，覆盖范围相当宽：Gmail 的搜索、阅读、起草、发送与标签管理；Drive 的文件检索、打开、创建与整理；日历的日程读取、事件创建与修改；Docs 的打开、阅读与编辑；Sheets 的区域读取、单元格更新与新建表格；以及 Google Chat 的空间与消息读写。插件可从 Cursor Marketplace 或应用内 Customize 页面安装。

同日 Cursor 还表示，其云端智能体在常规任务上的 token 效率提升 20%–30%，涉及电脑操作（computer use）的任务上提升约 80%，原因是调整了智能体处理 MCP 服务、skills 与电脑操作循环的方式。

这标志着什么转向

Cursor 的生意起于代码编辑器。而 Gmail 和日历并不是代码。这批插件意味着编码智能体不再被框在代码仓库里，而是开始接管工程师工作面的其余部分——从邮件线程里提取需求上下文、合并代码后同步更新规格文档、或在排长任务前先看一眼日历。

这条赛道同样拥挤。谷歌自己也在通过预览版 MCP 服务器和内置逾百个智能体技能的 Workspace CLI 向第三方开放，Claude Desktop、Gemini CLI 与 VS Code 均已接入。Cursor 的选择是自己做第一方插件，而不是让用户自行搭 MCP 服务。

为什么重要

对收件箱、网盘和日历的写权限，与对 git 分支的写权限是完全不同量级的风险面。一封被植入提示注入的邮件，如今具备了驱使智能体代发邮件或改动共享文档的现实路径，而业界对这类权限该如何收敛尚无定论。就市场而言，这说明编码智能体品类正在向通用企业智能体扩张——Cursor 的对手因此从其他 IDE，变成了谷歌与微软自家的生产力助手。
