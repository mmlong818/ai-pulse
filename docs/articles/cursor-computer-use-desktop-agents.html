Cursor gives coding agents control of desktop apps

Cursor’s new Computer Use feature lets coding agents click and type across desktop software, including simulators used to test mobile apps.

What happened

Cursor introduced Computer Use on October 23, extending its coding agents beyond browser-based workflows. The company said agents can click and type across applications on a user’s computer, and demonstrated the capability with the iOS Simulator. An agent can therefore build software, launch a local development tool, inspect the result and interact with the interface it has created.

Cursor’s documentation describes the feature as an explicit opt-in for self-hosted workers on macOS and Linux. The worker uses a helper application or a desktop display to capture the screen and send input events. Users must grant the required operating-system permissions, and desktop sharing can be enabled separately so an authorised person can watch or take control of the agent’s session.

That design is materially different from a browser agent. Browsers offer relatively constrained pages, predictable controls and clearer permission boundaries. Desktop software can expose local files, credentials, development environments and irreversible actions. Computer Use therefore turns the agent from a code-generation assistant into an operator of the machine where the code runs.

Why it matters

The feature points toward a more integrated coding loop: agents can test graphical interfaces, drive simulators, operate legacy tools and complete tasks that have no convenient API. This could reduce the gap between generating code and verifying whether a product actually works for a human user. It also raises the cost of mistakes. A misdirected click in a browser is inconvenient; the same action in a desktop environment could delete files, alter settings or expose private data. Cursor’s opt-in controls and human takeover path are important, but they do not yet establish how reliably agents identify risky actions or recover from visual ambiguity. The competitive question is whether desktop control becomes a dependable testing layer or remains an impressive but fragile demo.

Uncle Cat take

The iOS Simulator example is the substance here: Cursor is attacking the last mile between writing an app and proving its interface works, where ordinary code agents still stop short.
