MCP ships stateless spec, its biggest break since launch

The Model Context Protocol's 2026-07-28 revision retires protocol-level sessions, replacing the initialize handshake with self-contained requests.

The Model Context Protocol published its 2026-07-28 revision as a stable release on Tuesday, completing the largest architectural change since the standard appeared in late 2024. The headline shift is that MCP is no longer stateful at the protocol layer.

What changed

The initialize/initialized handshake and the Mcp-Session-Id header are both retired. Each request now carries its own protocol version, client identity and capability declarations in a _meta field, which means a server fleet can answer any request from any instance behind an ordinary load balancer without shared session storage.

Removing persistent streams forced a replacement for server-initiated requests. The new Multi Round-Trip Requests mechanism handles the common case where a tool needs mid-call input: the server returns a result typed input_required alongside the questions it needs answered, and the client re-issues the call with an inputResponses payload. Requests also now carry Mcp-Method and Mcp-Name HTTP headers so gateways and rate limiters can route and meter traffic without parsing JSON bodies, and the four listing methods plus resources/read return ttlMs and cacheScope hints for caching.

Authorization was tightened in parallel, with RFC 9207 issuer validation, client credentials bound to the issuing authorization server, and Dynamic Client Registration formally deprecated in favour of Client ID Metadata Documents. Tasks graduated out of the experimental core into a named io.modelcontextprotocol/tasks extension. Roots, Sampling, Logging and the legacy HTTP+SSE transport are all deprecated with a stated minimum twelve-month offramp.

The TypeScript, Python, Go and C# SDKs support the revision at release; Rust is in beta. The release candidate was frozen on 21 May, giving implementers roughly ten weeks to test against production traffic before the spec was finalised.

Why it matters

MCP has become the default wiring between models and external tools, and the maintainers say its SDKs now draw close to half a billion downloads a month. Making the transport stateless removes the main operational objection to running MCP servers at scale — sticky sessions — and moves the protocol from something that mostly ran locally toward something deployable as ordinary web infrastructure. The cost is a genuinely breaking migration for every existing server and client, spread across a one-year deprecation window.
