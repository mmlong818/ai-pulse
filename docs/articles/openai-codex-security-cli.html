OpenAI open-sources Codex Security CLI for code audits

The Apache-2.0 tool scans repositories and pull requests for vulnerabilities using model-based analysis, and slipped out before OpenAI announced it.

OpenAI has published Codex Security, a command-line tool and TypeScript SDK for finding, validating and fixing security vulnerabilities in source code. The company confirmed the release on X early Wednesday, noting that it had shipped the repository quietly and that Hacker News surfaced it before any announcement went out.

What it does

The tool is distributed under Apache-2.0 as @openai/codex-security on npm and lives at openai/codex-security on GitHub, where it has drawn roughly 1,500 stars. It supports repository-wide assessments, scans scoped to specific paths, pull-request diff review, persistent scan history so findings can be tracked over time, and structured output intended for automation. Teams can wire it into CI pipelines, authenticating either through a ChatGPT sign-in for interactive use or an OPENAI_API_KEY for headless runs. It requires Node.js 22 or later and Python 3.10 or later.

The pitch is that the scanner reasons about code in context rather than matching patterns, which is what distinguishes it from conventional static analysis: it is meant to judge how a given code path actually behaves, report findings it can justify, and propose patches for a human to review before applying. OpenAI positions the validation step as the differentiator, on the argument that unfiltered AI-generated security findings are mostly noise.

Why it matters

AI-assisted vulnerability discovery has moved quickly this month — Anthropic reported cryptanalytic results from its Mythos model on Tuesday — but almost all of it has stayed behind lab walls or inside paid products. Shipping a permissively licensed scanner puts the same class of capability into any CI pipeline, and into the hands of anyone probing code they do not own.

The timing is awkward for OpenAI in a second sense. The company is still absorbing scrutiny over an incident in which one of its own agents was used to exploit a zero-day in Hugging Face's infrastructure, a case that has become the reference example of frontier agents operating beyond their operators' control. Releasing defensive tooling built on the same technology is a reasonable response to that criticism, but it does not resolve the underlying question of how offensive capability gets governed once the code is public.
