Anthropic Launches Claude Ship for Automated PR Approval

Claude Ship lets coding agents review pull requests, repair defects and approve changes under team-defined policies in beta.

From review to release

Anthropic has launched Claude Ship, a beta workflow that lets Claude Code handle more of the path from a pull request to a merge decision. Developers can invoke the /ship command, after which the agent reviews the proposed changes, responds to feedback, makes fixes and determines whether the pull request meets the team’s approval rules.

The important shift is operational rather than cosmetic. Earlier coding assistants primarily generated patches or commented on code. Claude Ship treats the pull request as a managed process with explicit policies, rather than as a single request for code generation.

Policies become the control surface

Teams can define what Claude is allowed to approve and what requires human review. That distinction matters because code review contains more than bug detection: it involves repository conventions, test evidence, security considerations and risk tolerance. Anthropic’s design places those decisions in policy files and approval gates instead of leaving them to an informal chat with the model.

Anthropic says its own Claude Code team more than doubled the number of merged pull requests between June and September, while reverted changes fell by more than 40 percent. Those figures are company-reported and do not establish that Claude Ship will produce the same results for customers, but they explain the product direction.

The unresolved boundary

Automating review and approval raises a sharper question than whether a model can write code: which changes should an organization never allow an agent to approve on its own? A policy engine can constrain file paths, tests and required reviewers, but it cannot eliminate ambiguity in unfamiliar systems or guarantee that a passing test captures the real business risk.

Claude Ship nevertheless marks a meaningful product boundary. If it works reliably, coding agents become participants in software governance, not merely fast contributors. That could reduce review bottlenecks for routine changes while making policy quality—and the audit trail around exceptions—the new source of engineering leverage.
